=== NAVIGATIONSPRINZIPIEN ===

**1. Statische Navigation**
- Kein JavaScript für Navigation erforderlich
- Reine HTML-Links mit CSS-Styling
- Aktive Seite wird über CSS-Klassen markiert
- Mobiles Hamburger-Menü nur mit CSS (optional)

**2. Einheitliche Struktur**
- Identischer Header auf allen Seiten
- Identische Navigation auf allen Seiten
- Identischer Footer auf allen Seiten
- Konsistente CSS-Datei für alle Seiten

**3. Visuelle Hierarchie**
- Hauptnavigation immer sichtbar
- Aktive Seite hervorgehoben
- Klare Navigationsreihenfolge
- Mobile-First Ansatz

=== TECHNISCHE ANFORDERUNGEN ===
- Statische HTML-Seiten ohne dynamische Inhalte
- Relative Pfade für Ressourcen (css/style.css, js/script.js)
- Einheitliche CSS-Datei mit Navigation-Styles
- Responsive Design für alle Seiten
- GitHub Pages kompatibel
- Barrierefreie Navigation (ARIA-Labels, Tastatur-Navigation)

=== DESIGN-ENTSCHEIDUNGEN ===
1. **Navigation-Layout**: Horizontale Navigation im Header, mobile Ansicht als Hamburger
2. **Aktive Seite**: CSS-Klasse .active für visuelle Markierung
3. **Konsistente Farben**: Weiterführung des bestehenden Farbschemas
4. **Responsive Breakpoints**: 768px und 480px für mobile Ansichten
5. **Hover-Effekte**: Dezente Animationen für bessere UX

=== GRÜNDE FÜR STATISCHE MEHRSEITENLÖSUNG ===

**1. Übersichtlichkeit**
- Thematische Trennung reduziert kognitive Last
- Klare Fokussierung auf spezifische Inhalte pro Seite
- Bessere Orientierung für Nutzer

**2. Skalierbarkeit**
- Einfache Erweiterung um neue Themenbereiche
- Modulare Struktur ermöglicht gezielte Updates
- Bessere Wartbarkeit bei wachsendem Inhaltsumfang

**3. GitHub Pages Kompatibilität**
- Keine serverseitige Technologie erforderlich
- Schnelle Ladezeiten durch statische Dateien
- Einfache Deployment- und Hosting-Lösung

**4. Nutzererfahrung**
- Direkte Navigation zu gewünschten Themen
- Klarer mentaler Map der Plattform-Struktur
- Bessere Bookmark-Möglichkeiten für spezifische Inhalte

**5. SEO & Auffindbarkeit**
- Separate URLs für thematische Bereiche
- Gezieltere Optimierung pro Thema
- Bessere Indexierung durch Suchmaschinen

=== INTEGRATION BESTEHENDER INHALTE ===
- Alle vorhandenen Inhalte werden thematisch zugeordnet
- Texte werden gekürzt, aber nicht inhaltlich verändert
- Visuelle Elemente und Cards bleiben erhalten
- Didaktische Struktur bleibt vollständig erhalten
